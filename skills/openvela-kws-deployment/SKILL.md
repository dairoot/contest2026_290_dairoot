# 嵌入式离线唤醒词开发与部署到 openvela

把训练模型、流式判决和真实麦克风链路一起交付。目标是 openvela 本地运行的纯 C 唤醒引擎；Linux 在检出后接收事件。验证数值一致性、真实语音效果和实时预算，分别报告结果。

## 定位输入与实现

先定位包含 `tools/kws/` 和 `board/contest_board/` 的项目根目录，记为 `CONTEST_ROOT`。Skill 被单独安装时，需要另有项目源码 checkout；不要假设当前目录、个人 SSH 别名或历史板子地址可用。

从当前任务和源码确认唤醒词、板型、麦克风/采样率、训练设备、构建设备、目标板、数据位置，以及任务是复用模型、重训还是移植引擎。已有信息足够就继续，缺少真机或真人数据时先完成相应的离线阶段并标明验证边界。

本项目基线：RK3576 的 cpu3 运行 openvela，PDM 16 kHz 单声道采集，DS-CNN 在 CPU 上推理，检出经 RPMsg 通知 Linux。这里的 KWS 不依赖 RKNN。赛事唤醒词为“你好，openvela”；用于其他项目时按用户要求选词，并重新制作语料。

以执行代码和生成常量为准：

| 契约 | 源码位置（相对 `CONTEST_ROOT`） |
| --- | --- |
| 采样率、帧长、帧移、FFT、mel、特征窗 | `tools/kws/kws_common.py` |

| 导出权重、前端表、金标准向量 | `tools/kws/export_c.py` |

复现命令、依赖与脚本限制见 [项目执行参考](references/project-workflow.md)。进行训练或部署时再读取对应章节。

## 开发流程

### 1. 先证明音频输入正确

检查实际 PCM 的采样率、声道、格式、RMS、峰值和持续流速，再判断模型。当前引擎输入是 16 kHz、单声道、int16；不要直接喂历史 I2S 路线的 15625 Hz 数据。

在板上用 `MIC_INFO`、`KWS_INFO`、`KWS_PEEK` 区分“没有真实音频”“音频到达但特征异常”“模型分数不足”。GPIO、电源、CRU 和引脚复用必须按目标板设计确认；旧日志中的临时供电接法不是通用接线方案。

### 2. 建立与真实使用条件一致的数据集

- TTS 用于启动数据集，补充多读法、语速、停顿；用真实扬声器到麦克风的重录适配声学信道。
- 采集目标使用者的近/远/快/慢/轻声正例，同时采同一人的非唤醒句、远处谈话、电视声、底噪、提示音和近音硬负例。只加本人正例容易让模型把嗓音或房间底噪当成唤醒线索。
- 自动转写和能量切段只用于候选标注。抽听边界，纠正轻声首字被裁掉、多个短语粘连以及正负标签冲突。
- 原句、重录版及增强变体归同一组；真人连续录音按录音时段或说话人划分集合，避免同一段录音的相邻片段跨集合。调阈值用验证集，最终效果另用未参与选择的测试集。
- 归一化统计只从训练数据拟合。当前脚本有历史限制，见执行参考；不能直接宣称现有评测完全无泄漏。

### 3. 训练并用完整判决链选模型

增强、缓存、训练后运行 `eval_suite.py`，分别记录真人召回、负句误触率、背景音的事件数/总时长/每小时误触。模型选择不能只看训练准确率或窗口分类分数。

本项目前端为 float32 log-mel，随后做训练统计归一化和窗内 CMN。真实麦克风有底噪，合成语料的数字静音可能造成域差；按实测噪声分布构造训练和评测背景，不能把某个历史 dBFS 值当成所有硬件的常量。

短片段峰值过阈值用于统计召回；连续流事件数还受平滑、不应期、滞回及启动静默期影响。单独验证“一次唤醒 + 尾部底噪”不会重复触发，两次有间隔的唤醒都可触发。

### 4. 导出并验证 Python/C 契约

前端表、归一化参数与折叠 BatchNorm 的网络权重由同一导出过程生成，不手改生成头文件。更改前端常量或网络结构后重建受影响的缓存、模型和金标准。

用固件同源的 `kws_frontend.c`、`kws_nn.c`、`kws_engine.c` 构建 `kws_host`，先做本机对拍，再在目标架构跑相同向量。现有通过条件为每组最大特征误差 `< 5e-3` 且概率误差 `< 2e-3`；任一失败就定位差异，不能通过放宽阈值继续刷板。

`export_c.py --random` 只用于在隔离副本验证 C 实现，会覆盖生成文件，不能作为已训练的交付模型。

### 5. 构建、部署与真机复验

确认构建成功且固件来自这次导出，记录模型、生成头文件、固件的版本或哈希。烧录前检查目标板、分区容量和持久备份；部署属于当前授权范围时继续。首次 AMP 适配不能仅刷 `amp.img`，还需匹配的分区表和 Linux DTS。

按现有板级方式接入采集和线程；移植到其他 openvela 板时保留纯 C 核心，替换音频输入、调度和事件出口，不照抄 RK3576 地址、中断号或刷写方式。

上板验收覆盖：

- 重启后采集正常，启动静默期结束后可检出；`KWS_INFO` 的阈值与本次模型一致。
- 真人正例、近音负例、提示音回灌和连续背景音；检出计数、RPMsg 与 Linux `KEY_WAKEUP` 对应。
- 实测推理耗时、`drop` 增量和线程负载，特别测试 Linux 空闲降频及同时放音/推理场景。当前 80 ms 周期只是预算基线，不能引用旧 README 的“数 ms”替代测量。

## 按症状排障

| 症状 | 优先检查 |
| --- | --- |
| TTS 分数高，真麦几乎不醒 | 重录信道、真人读法、窗长、信噪比、数字静音与底噪差异 |
| 特定人的普通说话也唤醒 | 正负例比例、同人负例、数据切分、过拟合 |
| 一句话连续响多次 | 连续平滑分、滞回重武装、不应期与提示音回灌 |
| C 与 Python 对不上 | 生成文件是否同一版本、float32、Hann/mel 表、CMN、BN 折叠 |
| `drop` 持续增长 | 推理耗时、共享簇降频、线程优先级、采集与推理环容量 |
| 重启后输入全零 | 麦克风供电、Linux 覆盖时钟/引脚配置、采集启动时序 |

## 交付结果

交付模型/生成文件与复现入口、数据划分说明、带样本量和时长的评测结果、Python/C 对拍记录、真机负载与事件验证。明确区分“代码已检查”“本机对拍”“目标架构对拍”“真实声音上板”；短时背景音零事件不能写成长期零误唤醒保证。
